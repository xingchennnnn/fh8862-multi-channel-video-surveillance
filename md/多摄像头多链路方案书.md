> 项目: Fullhan FH8862 多路 RTSP 视频监控系统  
> 日期: 2026-05-14  
> 当前状态: 单路打通 → 扩展为 4 路

---

## 一、单路现状回顾

```
┌─────────────┐     RTSP(8554)     ┌──────────────┐     WebRTC WHEP    ┌──────────────┐
│  FH8862 板   │ ─────────────────→ │  Ubuntu 服务器 │ ────────────────→ │  浏览器前端   │
│  192.168.1.3 │                   │  192.168.1.1  │                   │              │
│  IMX415 4K   │                   │  mediamtx     │                   │  :8080        │
│  RTSP server │                   │  node server  │                   │              │
│  控制:9999    │ ←── TCP 命令 ──── │               │ ←── HTTP API ─── │              │
└─────────────┘                   └──────────────┘                   └──────────────┘

数据流 (纯 RTSP, 已弃用 PES):
  IMX415 → MIPI(4K) → ISP → VPSS(720p) → H.264 Encoder → Live555 RTSP → 板端:8554
                                                                        → Mediamtx 拉流

板端启动: ./demo  (无参数, 纯 RTSP 模式)
```

> **PES UDP 推流已弃用。** 当前及后续全部使用纯 RTSP 模式，Mediamtx 通过 RTSP 协议主动从板端拉流。

## 二、多路目标架构

```
                         ┌─────────────────────────────────────────┐
                         │            路由器 (Router)                │
                         │          网关: 192.168.1.10                │
                         │                                         │
        ┌────────────────┼────────────┬─────────────┬──────────────┤
        │                │            │             │              │
        ▼                ▼            ▼             ▼              ▼
   ┌─────────┐    ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
   │ Board 1 │    │ Board 2 │   │ Board 3 │   │ Board 4 │   │ Ubuntu  │
   │FH8862   │    │FH8862   │   │FH8862   │   │FH8862   │   │ Server  │
   │ .1.11   │    │ .1.12   │   │ .1.13   │   │ .1.14   │   │ .1.1    │
   │RTSP:8554│    │RTSP:8554│   │RTSP:8554│   │RTSP:8554│   │mediamtx │
   │CTRL:9999│    │CTRL:9999│   │CTRL:9999│   │CTRL:9999│   │node.js  │
   └─────────┘    └─────────┘   └─────────┘   └─────────┘   │web:8080 │
                                                            └─────────┘

控制链路 (每路独立):
  浏览器 ─── HTTP API ───→ node server.js ─── TCP ───→ Board1:9999
                                   │────────── TCP ───→ Board2:9999
                                   │────────── TCP ───→ Board3:9999
                                   └────────── TCP ───→ Board4:9999
```

**核心思路**: 每块板独立运行纯 RTSP，路由器组网，Ubuntu 集中代理全部流和控制。

## 四、板端部署

### 4.1 启动命令（每块板相同，零改动）

板端代码**无需任何修改**。每块板独立启动纯 RTSP：

```bash
# ===== 每块板执行相同的命令 =====
mount -t nfs 192.168.1.1:/mnt/nfs_share /mnt -o nolock
cd /mnt/driver && sh load_modules_FH8862.sh
cd led && insmod hello_world.ko
cp /mnt/imx415_mipi_attr.hex /home/
cd /mnt && ./demo          # 无参数 = 纯 RTSP, 不推 PES
```

四块板分别配置各自的静态 IP（11/12/13/14）后，执行上述相同命令即可。

### 5.2 node server.js — 多设备控制路由

前端通过 node server 代理控制命令，根据 `camera_id` 路由到对应板端。

**设备表:**
```javascript
const cameras = {
    1: { ip: '192.168.1.11', ctrlPort: 9999 },
    2: { ip: '192.168.1.12', ctrlPort: 9999 },
    3: { ip: '192.168.1.13', ctrlPort: 9999 },
    4: { ip: '192.168.1.14', ctrlPort: 9999 },
};
```

**所有现有 API 增加 `camera_id` 参数：**

| API | camera_id | 说明 |
|-----|-----------|------|
| POST /api/rotate | 1-4 | 旋转 180 度 |
| POST /api/osd/color | 1-4 | OSD 文字颜色 |
| POST /api/osd/text | 1-4 | OSD 文字内容 |
| POST /api/osd/text_enable | 1-4 | OSD 文字显示开关 |
| POST /api/osd/invert | 1-4 | OSD 反色模式 |
| POST /api/mask/color | 1-4 | Mask 颜色 |
| POST /api/mask/enable | 1-4 | Mask 全局开关 |
| POST /api/mask/region/set | 1-4 | Mask 区域设置 |
| POST /api/mask/region/del | 1-4 | Mask 区域删除 |
| POST /api/mask/type | 1-4 | Mask 类型(纯色/马赛克) |
| POST /api/mask/mosaic_size | 1-4 | 马赛克块大小 |
| POST /api/record/start | 1-4 | 设备端开始录像 |
| POST /api/record/stop | 1-4 | 设备端停止录像 |
| POST /api/led | 1-4 | LED 控制 |
| POST /api/time/sync | **不填** | 同步到**全部 4 块板** |

**时间同步 — 广播到全部板端:**

```javascript
// POST /api/time/sync
// 不需要 camera_id，同时同步全部 4 块板
app.post('/api/time/sync', (req, res) => {
    const timestamp = req.body.timestamp || Date.now();
    const cmd = 'TIME_SYNC ' + timestamp;
    
    let pending = Object.keys(cameras).length;
    let results = [];
    
    Object.entries(cameras).forEach(([id, cam]) => {
        sendBoardCommand(cam.ip, cmd, (err, resp) => {
            results.push({ camera_id: parseInt(id), ok: !err, response: resp });
            if (--pending === 0) {
                res.json({ ok: true, results });
            }
        });
    });
});
```

**server.js 修改要点:**
- 所有控制类 API 的请求体增加 `camera_id` 字段
- `sendBoardCommand()` 根据 `camera_id` 查 `cameras` 表获取目标 IP
- `/api/time/sync` 遍历全部 4 块板并发发送，汇总结果返回

## 九、潜在问题和应对

### 9.1 带宽

4 路主码流 = 8Mbps，4 路子码流 = 2.8Mbps。千兆交换机绰绰有余。**建议默认加载子码流**，点击单路放大再切主码流。

### 9.2 Mediamtx 并发拉流

`sourceOnDemand: yes` 保证没有观看时不拉流。4 路同时观看时 Mediamtx 同时维护 4 个 RTSP 客户端连接到 4 块板。

### 9.3 板端时钟同步

前端点击"时间同步"→ node server 并发向 4 板发送 `TIME_SYNC` 命令。时间精度取决于网络延迟（局域网内 <1ms 差异）。

### 9.4 IP 地址固定

板端必须配置静态 IP（或在路由器上 DHCP MAC 绑定），否则 IP 变化后 Mediamtx 和 node server 都无法正确连接。
